# Tenant databases (MariaDB) — design

Date: 2026-11-13. Status: implemented on branch `m2d-databases`.

## Goal

Tenants get MariaDB databases so their PHP, Node.js and Python sites can run
real applications (WordPress and the like), without giving one tenant any
reach into another's data or into the server itself. MariaDB is an optional
host package, like PHP: detected, reported, and refused cleanly when absent.

## Model

Two kinds of object, each with a record under `/var/lib/oxpanel`:

- **database** (`databases/<name>.json`): name, tenant, engine, state;
- **database user** (`db-users/<name>.json`): name, tenant, engine, state,
  `MAX_USER_CONNECTIONS`, the databases it is granted. No password, no hash.

Records are the proof of ownership, exactly as for POSIX accounts. Without a
record nothing is altered or dropped, and a name that already exists on the
server without one is refused, never adopted. States (`provisioning`, `ready`,
`deleting`) make every RPC resumable: the record is written before the
statement, and a repeated request finishes what a crash interrupted.

RPCs: `CreateDatabase`, `ListDatabases`, `DeleteDatabase`,
`CreateDatabaseUser`, `ListDatabaseUsers`, `SetDatabaseUserPassword`,
`DeleteDatabaseUser`, `GrantDatabaseAccess`, `RevokeDatabaseAccess`. Mutations
need the `vhost` scope (managing a site's database is site management, done by
the customer in a hosting panel); the lists need `read`.

## Naming

`<tenant>_<suffix>`, suffix `^[a-z0-9]{1,24}$` (`validate::DbName`). Tenant
names may themselves contain `_`, so the rule that makes ownership
unambiguous is that the suffix may not: the owner is always the text before
the *last* `_`. `acme_shop_wp` belongs to tenant `acme_shop`; tenant `acme`
cannot create it, and no two tenants can produce the same name. The longest
name is 32 + 1 + 24 = 57 characters: within MariaDB 10.5's limits (64 for a
database, 80 for a user) and PostgreSQL's 63, so a second engine keeps the
same rule. The character set needs no escaping in an SQL identifier or
string (no quote, backtick or backslash), but every identifier is quoted
anyway. MariaDB's own schemas and accounts are refused by name.

**Wildcards.** In `GRANT … ON db.*` the database is a `LIKE` pattern; `_`
matches any character. Grants are therefore written with `_` (and `%`, `\`)
escaped — `` `acme\_shop`.* `` — so a grant on `acme_shop` cannot cover
`acmeXshop`, and Reconcile compares grants by their stored pattern. The
reverse risk is a pattern written by hand that covers a tenant's future
database: a stock MariaDB install grants the anonymous account everything on
`test\_%`, so a tenant named `test` would have its databases shared with
every local user. `CreateDatabase` refuses a name that any unmanaged
account's database-level pattern covers, and Reconcile reports such an
account against existing databases. HANDBOOK §3.5 removes the anonymous
accounts and `test` grants as part of the install.

## Talking to the server

The daemon runs the distribution's `/usr/bin/mariadb` client as root over the
UNIX socket (`--no-defaults --protocol=socket --socket=… --user=root --batch
…`; constant argv) and writes the statements to its **standard input**. Root
authenticates through `unix_socket`, the AlmaLinux default, so there is no
administrative password to store. Every mutation first reads the server state
in one round trip (`SNAPSHOT_SQL`: schemata, accounts from
`mysql.global_priv`, global/schema/table/column/routine/proxy/role grants),
which is what lets a request that cannot succeed be refused before a record
is written, and what Reconcile compares against.

Alternatives rejected:

- **A Rust driver** (`mysql_async`, `sqlx`): parameterised values, but
  identifiers (database and user names) cannot be parameterised anyway, so the
  allow-list + quoting is needed either way; it adds a large dependency tree
  and a second way of spawning I/O outside the `System` trait, and the
  `FakeSystem` tests could no longer assert the exact SQL sent. The client
  binary keeps the "every external effect goes through `System` and is
  asserted exactly" property. Cost: one process per request (~10 ms).
- **SQL in `-e`**: puts the statements in the process list. Never used.

## Passwords

The password arrives in the request, is validated (8–128 characters, no
control characters — the engine's last line of defence; policy is the
panel's), hashed in memory, and forgotten. The daemon computes what MariaDB
stores for `mysql_native_password` (`*` + hex `SHA1(SHA1(pw))`) and sends only
that: `IDENTIFIED VIA mysql_native_password USING '*…'`. The plaintext
therefore never reaches an argument vector, the server's process list, its
general or binary log, or the journal. The hash is still sensitive (it can be
attacked offline), so it is only ever on the client's stdin, `CommandSpec`'s
`Debug` redacts it, and when such a statement fails the client's stderr
(which echoes the statement) is withheld from the journal and reduced to the
error number in the returned error.

`oxpanel-ctl` reads passwords from standard input, never from arguments.

Plugin choice: `mysql_native_password` is the one every client tenants will
use supports (PHP's mysqlnd does not support `client_ed25519`; MariaDB has no
`caching_sha2_password`). Its hash is weak by modern standards; the
mitigation is that it never leaves root-only places. Switching to `ed25519`
later is a change in `db::mariadb` only (`PasswordHash` + the plugin name).

A repeated `CreateDatabaseUser` cannot verify the password (nothing is
stored), so it confirms the user and leaves the password unchanged; the API
documents that `SetDatabaseUserPassword` is the way to change it. If the
account vanished from the server, `SetDatabaseUserPassword` re-creates it with
its recorded grants — the request carries everything that is needed.

## Privileges

An account is `'<name>'@'localhost'` — UNIX socket only (or loopback TCP if
the operator left networking on; HANDBOOK §3.5 turns it off with
`skip-networking`). It is created with `USAGE` only and gets, per granted
database of the same tenant:

`SELECT, INSERT, UPDATE, DELETE, CREATE, DROP, REFERENCES, INDEX, ALTER,
CREATE TEMPORARY TABLES, LOCK TABLES, EXECUTE, CREATE VIEW, SHOW VIEW,
CREATE ROUTINE, ALTER ROUTINE, TRIGGER`

— what an application and its migrations need. Deliberately absent:
`GRANT OPTION` (a tenant must not hand out access), `EVENT` (scheduled work
runs outside any connection and outside the tenant's suspension),
`DELETE HISTORY`, and every global privilege (`FILE`, `PROCESS`, `SUPER`,
`RELOAD`, `SHUTDOWN`, `CREATE USER`, `SHOW DATABASES`, replication, …).
A test pins the list.

## Limits

`MAX_USER_CONNECTIONS` per account (default 25, `OXPANEL_DB_MAX_USER_CONNECTIONS`),
recorded with the user and checked by Reconcile. Caps per tenant: 20
databases and 20 users (`OXPANEL_DB_MAX_DATABASES`, `OXPANEL_DB_MAX_USERS`).
Database size is reported by `ListDatabases` (data + index length from
`information_schema.TABLES`). Not included: size quotas (MariaDB has none
cheaply), per-user query/update rate limits (`MAX_QUERIES_PER_HOUR` exists but
is a poor fit for web workloads).

## Tenant lifecycle

- **DeleteTenant refuses** while the tenant owns databases or users, the same
  rule as for virtual hosts: dropping data is always an explicit request.
  Considered: cascading the drop. Rejected because it turns a mistaken
  `DeleteTenant` into irrecoverable data loss with no backups in the engine.
- **Suspend** locks every account of the tenant (`ACCOUNT LOCK`) and ends its
  open sessions (`KILL USER`; a lock alone leaves connections open). It runs
  last, after PHP and applications stopped, so nothing reconnects. Users
  created while suspended are born locked. **Resume** unlocks first, before
  PHP and applications start. A tenant without database users never touches
  MariaDB, so suspension works on hosts without it. If MariaDB is down while
  a tenant with database users is suspended, the request fails after the
  sites already answer 503 and the record stays unsuspended; repeating it
  completes it (the usual retry semantics).
- **DeleteDatabase** revokes the database from the tenant's users first, then
  drops it, then updates the users' records.

## Reconcile

Read-only, `SELECT`s only. Kinds (`DriftKind` 22–25):

- `DATABASE_MISSING`: recorded database not on the server; interrupted record;
  or MariaDB not reachable while records exist (one finding, subject `mariadb`).
- `DATABASE_USER_MISSING`: recorded account not on the server; interrupted record.
- `DATABASE_PRIVILEGE_DRIFT`: per user — global privileges, table/column/
  routine/proxy/role grants, grants on databases the record does not list,
  privileges beyond or short of the fixed list, `GRANT OPTION`, a different
  connection limit, a lock state that disagrees with the tenant's suspension,
  another authentication plugin. Per database — an unmanaged account whose
  pattern covers it.
- `ORPHAN_DATABASE_OBJECT`: a database or account carrying an existing
  tenant's prefix without a record.

## Hardened unit and SELinux

The daemon's unit needed no change: `/var/lib` is already in `ReadWritePaths`
(connecting to a UNIX socket needs no write access to its mount anyway), and
`PrivateNetwork=yes` does not affect path-based sockets. `/usr/bin/mariadb`
was added to `system::bin`. The client reads no option file (`--no-defaults`).

SELinux: the daemon (unconfined service domain) may run the client and
connect. PHP runs in `httpd_t`, applications in `oxpanel_app_t`; both reach
`mysqld_t`'s socket under the stock policy plus OxPanel's module as it was
(verified on the acceptance VM, zero denials) — no rule was added.

## More engines (PostgreSQL, MongoDB)

Shaped so a second engine is added beside MariaDB without renaming anything:

- **API.** RPC and message names are engine-neutral (`CreateDatabase`,
  `DatabaseUser`, …). `enum DatabaseEngine` (`UNSPECIFIED` = MariaDB, `MARIADB`)
  is a field of `CreateDatabaseRequest`, `CreateDatabaseUserRequest`,
  `Database` and `DatabaseUser`; `GetHostInfo` reports a *list* of
  `DatabaseEngineInfo`, so a new engine is a new enum value and a new list
  entry, not new fields.
- **Names are unique across engines** (one namespace per tenant). Every call
  after creation addresses an object by name alone, records stay keyed by
  name, and caps are per tenant across engines. Grants require user and
  database on the same engine (checked).
- **Records** carry `engine` (`"mariadb"`; absent reads as MariaDB; an
  unknown value fails to load — fail closed).
- **Code.** `db/mod.rs` is the engine-independent workflow; `db/mariadb.rs` is
  the only code that builds SQL for or talks to MariaDB. PostgreSQL becomes
  `db/postgres.rs` (driving `psql` the same way, as `postgres` via peer
  authentication) and the places in `db/mod.rs` that call `mariadb::` gain a
  `match record.engine`. Config is per engine where it must be
  (`OXPANEL_MARIADB_SOCKET`) and shared where it can be (`OXPANEL_DB_*` caps).
- **Naming** already fits PostgreSQL's 63-byte identifiers; its reserved names
  (`postgres`, `template0/1`, `pg_*`) are not producible by the grammar except
  `postgres_*` for a tenant called `postgres`, which would be added to the
  reserved list with the engine.

What a second engine will need that is not abstracted now (on purpose: one
implementation is not enough to design the interface): a trait or enum
dispatch for snapshot/execute/sizes, and per-engine privilege lists.

## Not included

Other engines; remote access; per-database size quotas; database backups or
dumps (the backup stream); importing existing databases (adoption is refused
by design); renaming; per-user privilege subsets (read-only users); tenant
self-service tools such as phpMyAdmin.

## Verification

See the final report of the stream for the exact counts: unit tests with
exact SQL/argv assertions against an emulated MariaDB in `FakeSystem`
(`system/fake_mariadb.rs`, which rejects any statement it does not know), two
gRPC end-to-end tests, the integration section in `run-inside.sh` against a
real MariaDB 10.5 (PHP page reading and writing its database, cross-tenant and
`mysql.*` refusals, injection attempts, password absent from `ps`, the
journal and the server's process list, suspension locking and killing
sessions, reconcile catching a hand-made grant), and `INSTALL=rpm make
acceptance` on AlmaLinux 9 with SELinux enforcing.

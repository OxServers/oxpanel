# OxPanel engine — feature list (v0.2.0)

This is what `oxpanel-daemon` **does today**, as verified by the test suites
(`make test`, `make integration`). Anything not listed here is not implemented;
see "Not yet included" at the end so nobody assumes otherwise.

## Tenant accounts

| Feature | Detail |
|---|---|
| Create tenant | Dedicated POSIX user **and** primary group with the same numeric id (when free), allocated from a reserved uid range (default `20000–29999`, lowest free id), login shell `/sbin/nologin`, password locked, GECOS `OxPanel tenant`. |
| Private home | `<home_base>/<username>` (default `/home/<username>`), mode `0700`, owned by the tenant. Mode and ownership are re-verified and repaired on every provisioning pass. |
| Resource limits (cgroups v2) | Per-tenant systemd slice `oxpanel-tenant-<name>.slice` carrying `MemoryMax` (plus `MemorySwapMax=0`), `CPUWeight`, `IOWeight`, `TasksMax`; a `user-<uid>.slice.d/50-oxpanel.conf` drop-in applies the same limits to any future login session. Written as unit files and applied with `systemctl daemon-reload` — the daemon never writes `/sys/fs/cgroup`. |
| Safe unit naming | Tenant names are systemd-escaped (`foo-bar` → `oxpanel-tenant-foo\x2dbar.slice`) so one tenant's slice can never be nested under another's. |
| Owner label | Optional opaque `owner` string (e.g. a reseller id) stored on the tenant and usable as a filter in `ListTenants`. The engine never interprets it. |
| Get / list | `GetTenant`, `ListTenants` (optionally filtered by owner). |
| Delete tenant | `userdel`, optionally with `--remove` (home directory), removes the slice unit and drop-in, scheduled tasks and the backup schedule, SFTP access (sessions ended first) and the uid's disk quota. Refused — before anything is changed — while the tenant still owns virtual hosts, databases, database users or deleted databases in its trash, backups that are not retained, or has a job running. Retained backups outlive it, detached from the name. |
| Delete tenant with everything (cascade) | `DeleteTenant` with `cascade` removes, in this order and as a job (`GetJob`): a file-manager job left running (stopped), PHP and applications, scheduled tasks, every site with its certificate and Automatic HTTPS state, SFTP access, database users, databases and the database trash (dropped at once, no 30-day trash), backups that are not retained, the backup schedule, then the account and its home with the file manager's partial uploads, its file-job history and upload records. It is refused (`FAILED_PRECONDITION`, nothing written) while a backup, restore or file job of the tenant runs; while it runs, the tenant's files are not changed through the file manager and no other job starts. Only when the request repeats the tenant's name (`confirm_username`) — anything else is `INVALID_ARGUMENT` and touches nothing — and with the `delete` scope. Optional final backup (files and databases) kept for 1–366 days (`final_backup_retain_days`): nothing is deleted unless it completes and is retained. The job survives a daemon restart (re-driven at start-up); a half-done deletion is completed by repeating the request. A new tenant of the same name sees nothing of the old one. |
| SELinux | On SELinux-enabled hosts the home is relabelled with `restorecon -R` after creation. |
| Idempotent | Repeating `CreateTenant` with an identical specification returns the existing tenant (`created=false`); a different specification is refused (`ALREADY_EXISTS`). |
| Resumable | The tenant record is written **before** `useradd`; if the daemon crashes at any point, the next identical request resumes the remaining steps. Records carry a state: `provisioning`, `ready`, `deleting`. |
| Never adopts foreign accounts | A user or group that exists but was not created by OxPanel is refused (`FAILED_PRECONDITION`), and can never be deleted through the API. |
| Update limits | `UpdateTenantLimits` replaces the tenant's limits (a complete set, not a patch): both unit files are rewritten and applied with `daemon-reload`, so the new values are live immediately. Repeating the call completes an interrupted attempt. |
| Update owner | `UpdateTenantOwner` replaces or clears the owner label (e.g. moving a customer to another reseller). Touches no OS state. |
| Suspend / resume | `SuspendTenant` re-renders every virtual host of the tenant to answer `503` with `Retry-After` and no document root, validates once and reloads; all files are restored if Nginx rejects the result. Files, limits and the account are untouched; sites added while suspended are born suspended. `ResumeTenant` reverses it. Across features the order is: the sites answer 503 first, then a running file-manager job is stopped and the files become read-only, then PHP and applications stop, then access is cut (SFTP keys, password and sessions; database accounts locked and their sessions ended, last); resume is the exact reverse, and Automatic HTTPS catches up afterwards. |
| Usage | `GetTenantUsage`: current memory, total CPU time and task count from systemd (tenant slice + login-session slice), and disk space: from the quota system where disk quotas are enforced (no tree walk), otherwise allocated under the home (`du`, one file system, no symlink following). |
| Disk quotas | `ResourceLimits.disk_max_bytes` / `inodes_max` (`--disk 5G --inodes 200000`), set at creation and by `UpdateTenantLimits`: an **XFS user quota** enforced by the kernel — everything the tenant's uid owns on the file system holding the homes counts, whoever wrote it (SFTP, PHP, an application), and a write beyond it fails with "Disk quota exceeded". The host must mount that file system with `uquota` (handbook §9.1; the daemon never remounts or edits fstab). Where it does not, `GetHostInfo` says so (`disk_quota_available=false` and what to change) and a disk limit is refused with `FAILED_PRECONDITION` before anything is created — never silently accepted. Every tenant's kernel limits are set (including "none", so a re-used uid inherits nothing) and verified against the quota report; deletion clears them. |
| Reserved names | `root`, `nginx`, `apache`, `oxpanel*`, `systemd-*`, `wheel`, `sudo`, … are rejected before anything touches the OS. |

## Virtual hosts (Nginx)

| Feature | Detail |
|---|---|
| Configure | One server block per domain: `listen 80` / `listen [::]:80`, `server_name <domain> <aliases…>`, `root <home>/<document_root>`, `index index.html index.htm`, `try_files`. |
| Per-site logs | Every virtual host writes its own `<domain>.access.log` and `<domain>.error.log` under `/var/log/nginx/oxpanel` (closed to tenants), rotated daily for 14 days by the shipped logrotate rule and removed with the site. `ReadVirtualHostLog` returns the end of either log (whole lines, 32 KiB by default, at most 128 KiB) so the panel can show it without shell access. |
| PHP source is never served | On a virtual host without PHP, `*.php` answers 404 instead of handing out the script as a download. |
| Start-up convergence | At start the daemon re-renders every virtual host from its record, so files written by an older version pick up the current template (validated and rolled back like any other change). Application and scheduled-task units that exist but differ from what this version renders are written again too (`daemon-reload`; a running application is `try-restart`ed unless its tenant is suspended; a task's timer is applied as after `PutScheduledTask`). Unit descriptions, which systemd writes into the journal the account's owner reads in the panel, say "account", not "tenant". |
| Aliases | Up to 50 additional server names per virtual host. Every server name is unique across the whole host; a name owned by another tenant is refused. |
| Document root | Relative to the tenant home (default `public_html`), **created as the tenant** (privileges fully dropped via `setpriv`), then verified to be a real directory owned by the tenant. |
| Web-server access without opening the home | POSIX ACLs give the web user (`nginx`) traverse (`--x`) on the path and read (`r-x`) on the document root, plus a default ACL so new files inherit it. The home stays closed to everyone else (`group::---`, `other::---`). ACLs are set with `--physical`, so a planted symlink is skipped. |
| Hardened server block | `disable_symlinks if_not_owner` (symlinks to files the tenant does not own are refused), dot-files (`/.env`, `/.git`) answered with 404, `autoindex off`, `server_tokens off`. |
| Validate → activate → roll back | Config written atomically (`tempfile` + `rename` + `fsync`), checked with `nginx -t`; only then `systemctl reload-or-restart nginx`. If validation fails the previous file (or its absence) is restored and the error text is returned. |
| Catch-all default server | On first use the daemon installs `/etc/nginx/conf.d/00-oxpanel.conf` with an `include` of its directory **and** a `default_server` that closes the connection (`return 444`), so unknown host names and bare-IP requests never reach a tenant's site. Validated with `nginx -t`; rolled back if the host already defines a default server (configurable). |
| SELinux | On SELinux-enabled hosts the document root is made label-equivalent to `/usr/share/nginx/html` (`semanage fcontext -e`, so the tree is `httpd_sys_content_t` even though the policy's own `file_contexts.homedirs` would label `~/public_html` differently; a plain rule is overridden), committed without a kernel policy reload, then `restorecon -RF` (the policy creates `~/public_html` as the *customizable* `httpd_user_content_t`, which plain `restorecon` refuses to change); removed again when the last virtual host using that root is removed. Requires the `httpd_enable_homedirs` and `httpd_read_user_content` booleans, which the RPM sets and the daemon checks at start-up. |
| Remove / list | `RemoveVirtualHost` (config removed, validated, reloaded), `ListVirtualHosts` (optionally per tenant). |
| Idempotent | Re-sending an identical configuration changes nothing and reports `created=false`. |

## PHP (per-tenant PHP-FPM)

| Feature | Detail |
|---|---|
| Opt-in per virtual host | `ConfigureVirtualHost` with `php=true`. Refused with `FAILED_PRECONDITION` if `php-fpm` is not installed; `GetHostInfo.php_available` tells the panel in advance. |
| One FPM instance per tenant, running as the tenant | Not a pool inside a shared root-owned master: the whole instance (master and workers) runs under the tenant's uid through its own systemd unit `oxpanel-php-<name>.service`. No PHP process ever runs as root or as another tenant. |
| Inside the tenant's limits | The unit lives in the tenant's slice, so `MemoryMax`, `CPUWeight`, `IOWeight` and `TasksMax` bound PHP, and `GetTenantUsage` reports it. At most 8 workers, started on demand and stopped when idle. |
| Sandboxed unit | `NoNewPrivileges`, empty capability set, `ProtectSystem=strict` with only the tenant's home writable, private `/tmp` (sessions and uploads are per tenant), `PrivateDevices`, `ProtectKernel*`, `RestrictNamespaces`. |
| Socket only the web server can reach | UNIX socket `/run/oxpanel-php/<name>/php.sock` with an ACL naming the web-server account. Other tenants cannot connect; there is no TCP listener. |
| Confined scripts | `open_basedir` limits file access to the tenant's home and `/tmp`; `allow_url_include` and `display_errors` are off; only `.php` is executed. |
| Safe Nginx hand-off | `try_files $uri =404` before `fastcgi_pass` (a script that does not exist is never passed on, which closes the `image.jpg/x.php` path-info trick), `SCRIPT_FILENAME` built from `$realpath_root`, dot-directories excluded, `X-Powered-By` hidden. Unknown paths fall back to `/index.php` (front controllers such as WordPress work without rewrite rules). |
| Lifecycle | The instance is created with the tenant's first PHP-enabled virtual host and removed with the last one. It is enabled, so it returns after a reboot. Suspending the tenant stops and disables it (after the sites answer 503); resuming starts it before the sites return. |
| SELinux | Works enforcing with zero denials. PHP runs in the web-server domain; the RPM sets `httpd_unified` so a tenant's PHP can write the tenant's own files (uploads, caches). Without the boolean PHP is read-only and the daemon logs a warning at start. |
| Reconciliation | A missing or edited pool configuration or unit is reported as `PHP_POOL_DRIFT`, stray ones as `ORPHAN_PHP_POOL`. |
| Settings per site | `SetPhpSettings` (`vhost` scope: the customer may tune its own sites; `oxpanel-ctl php set`) sets, per PHP site, exactly these and nothing else: `memory_limit` (16 MiB … max), `upload_max_filesize` and `post_max_size` (1 MiB … max; post at least upload, upload + 1 MiB when only the upload size is given), `max_execution_time` and `max_input_time` (1 s … max), `max_input_vars` (100 … max), `display_errors`, `date.timezone` (an IANA zone that exists in the host's time-zone database). Values are numbers and flags the engine renders itself; anything out of bounds is refused with `INVALID_ARGUMENT` before a file is touched; a site without PHP is `FAILED_PRECONDITION`. An empty request restores PHP's defaults; `ConfigureVirtualHost` keeps the settings. `VirtualHost.php_settings` / `php_settings_effective` report them. |
| Applied in a pool of the site's own | A site with settings gets its own pool (and socket) inside the tenant's PHP-FPM instance, with the same hardening as the default pool (`open_basedir`, `allow_url_include` off, private upload and session directories — none of which can be changed) plus its settings as `php_value`: one site's settings never reach another site, which `fastcgi_param PHP_VALUE` cannot guarantee (FPM keeps such values in the worker). A tenant whose sites set nothing keeps byte-identical files. Scripts may still change what PHP lets them (`ini_set`, `set_time_limit`), as on any PHP host: the real ceiling for memory is the tenant's `MemoryMax`. `max_execution_time` counts the script's CPU time (PHP's rule on Linux). |
| Nginx follows | When a size or time setting is used, the site's server block raises `client_max_body_size` to `post_max_size` and the FastCGI read/send timeouts to the execution/input time + 30 s (at least Nginx's 60 s); otherwise a larger upload limit would end in 413 and a longer execution time in 504. |
| Host maxima and plan caps | Host maxima `OXPANEL_PHP_MAX_MEMORY_MB` (1024), `_UPLOAD_MB` (256, upload and post), `_EXECUTION_SECS` (300), `_INPUT_TIME_SECS` (300), `_INPUT_VARS` (10000), reported by `GetHostInfo.php_limits`. Per tenant (a plan): `SetTenantPhpLimits` (`tenant` scope; `oxpanel-ctl php limits`), each cap within the host maximum, 0 = the host maximum. Lowering a cap clamps what is rendered at once; the site's requested values stay in its record. |

## Node.js and Python applications

| Feature | Detail |
|---|---|
| Opt-in per virtual host | `ConfigureVirtualHost` with `app { runtime: NODE | PYTHON, root, entry }` (defaults: `apps/<domain>`, `app.js` / `app.py`). Cannot be combined with `php`. Refused with `FAILED_PRECONDITION` if the runtime is not installed, or if Node.js is older than **22** (the minimum supported); `GetHostInfo` reports `node_available`, `node_version` and `python_available`. |
| One service per application, running as the tenant | `oxpanel-app-<domain>.service`: `User=<tenant>`, in the tenant's slice (so the tenant's limits bound it and `GetTenantUsage` counts it), sandboxed like PHP (`NoNewPrivileges`, empty capability set, `ProtectSystem=strict` with only the tenant's home writable, private `/tmp`). Restarted automatically if it crashes; enabled, so it returns after a reboot. |
| No TCP ports | The application listens on a UNIX socket whose path it receives in `PORT` and `OXPANEL_SOCKET` (`server.listen(process.env.PORT)` works unchanged in Node.js). The socket directory is `0750` with an ACL for the web server only: other tenants can neither enter it nor connect, and there are no ports to allocate or collide. |
| Source is never web-readable | The application directory gets no web-server ACL and must not be the document root or inside it. Nginx serves files that exist in the document root itself (static assets) and proxies everything else, including WebSocket upgrades, to the application; `X-Forwarded-For`/`-Proto` and `Host` are passed on, `X-Powered-By` is hidden. |
| Python virtualenv | Every Python application gets its own virtualenv (`<root>/.venv`), created as the tenant. The application runs with that interpreter, so its packages are its own. |
| Dependencies | `InstallAppDependencies` runs `npm install --omit=dev` or `pip install -r requirements.txt` (into the virtualenv) as the tenant, in a sandboxed transient unit inside the tenant's slice with a 4-minute limit, returns the installer's output, and restarts the application on success. A failing installer is a result, not an error. |
| Restart and output | `RestartApp` (after new code is in place; also clears a crash loop). `ReadVirtualHostLog` with kind `APP` returns the application's recent stdout/stderr from the journal. |
| Lifecycle | The unit is removed when the application is switched off or the virtual host is removed; the code stays (it is the tenant's data). Suspension stops and disables every application of the tenant after the sites answer 503; resume starts them before the sites return. |
| SELinux | Works enforcing with zero denials. Applications run in their own domain, `oxpanel_app_t` (a small CIL module shipped with the package), so the web server is allowed to connect to application sockets and to nothing else; socket directories are labelled `httpd_var_run_t`. If the module is missing, enabling an application is refused with the command that installs it. |
| Reconciliation | An edited or missing application unit is `APP_UNIT_DRIFT`, a stray one `ORPHAN_APP_UNIT`. |

## Scheduled tasks

| Feature | Detail |
|---|---|
| What a task runs | `PutScheduledTask` (create or replace, idempotent; `vhost` scope; `oxpanel-ctl task set`): a PHP script (`/usr/bin/php -f`, needs `php-cli`), a Node.js script, a Python script (the system's `python3` or a virtualenv of the tenant), each relative to the home with up to 16 arguments; or a URL of one of the tenant's own sites, fetched by `curl` pinned to this host. Never a command line: the interpreter is the engine's choice, no shell is involved. A runtime that is not installed is refused with `FAILED_PRECONDITION`, as for applications. |
| Runs as the tenant | A oneshot systemd service per task, `User=` the tenant, in the tenant's slice (its limits apply, `GetTenantUsage` counts it), sandboxed like an application (`NoNewPrivileges`, no capabilities, `ProtectSystem=strict` with only the home writable, private `/tmp`), the engine's socket not even visible. Another tenant's files and the system stay closed. |
| Nothing injectable | Names `a-z 0-9 -`; scripts and virtualenvs relative paths without `..`; arguments printable ASCII without quotes, backtick, backslash, `$` or `%`; URLs `http(s)` without user, password or port, the host one of the tenant's server names, the path allow-listed. Every word of the unit's command line is written quoted with systemd's expansions escaped: no field can add a directive, escape the sandbox or run as anyone else. |
| Schedules | Every N minutes (N dividing 60, at least `OXPANEL_TASK_MIN_INTERVAL_MINUTES`, default 5), every N hours at a minute, daily, weekly or monthly (day 1–28) at a time, in UTC or an IANA time zone — integers mapped by the engine onto `OnCalendar=`. Each timer has a fixed random delay (up to the period, at most 15 minutes), so many tenants' "every hour" do not start in the same second. Missed runs are not caught up. At most `OXPANEL_TASK_MAX_PER_TENANT` (20) tasks per tenant. |
| Time limit, no overlap | A time limit per task (10 s … `OXPANEL_TASK_MAX_TIMEOUT_SECS`, default 300 s): at the limit the task is ended with everything it started. A task still running is never started a second time. |
| Status, output, run now | `ListScheduledTasks` (`read`): on/off, running, last start and end, result (`success`, `exit-code`, `timeout`, …) and exit status, next run (systemd's state since the host started). `ReadScheduledTaskLog`: the end of its output, from the journal. `RunScheduledTask` (`vhost`): run now, also a task that is switched off. A script that is gone fails visibly. |
| Lifecycle | `enabled` per task. Suspension stops and disables every timer and running task of the tenant; resume enables the timers of enabled tasks again; tasks saved while suspended wait. `DeleteTenant` (plain and cascade) removes the tenant's tasks first. `DeleteScheduledTask` removes one. |
| SELinux | Tasks run in the application domain `oxpanel_app_t`; works enforcing with zero denials. |
| Reconciliation | A task unit missing or not what its record renders, or a timer enabled when it should not be (or the reverse), is `TASK_UNIT_DRIFT`; an `oxpanel-task-*` unit without a record is `ORPHAN_TASK_UNIT`. |

## HTTPS (certificates)

| Feature | Detail |
|---|---|
| Bring your own certificate | `InstallCertificate` takes the chain and the unencrypted private key (RSA or EC) in the request body. OpenSSL confirms the key belongs to the certificate; the daemon checks the validity period and that the certificate covers the domain (wildcards cover one label). Aliases it does not cover are reported (`uncovered_names`), not refused. Anything that fails is refused with the reason before a file is touched. `RemoveCertificate` makes the site HTTP-only again. |
| Automatic certificates (ACME, HTTP-01) | `RequestCertificate` obtains a certificate for the domain and all aliases from Let's Encrypt (or any ACME directory set in `OXPANEL_ACME_DIRECTORY_URL`, e.g. staging or a private CA). Renewed automatically 30 days before expiry (checked 5 minutes after start and every 12 hours; `RenewCertificates` does it now). A refusal by the authority is a result with its reason, not an error; the site keeps its previous certificate. |
| Automatic HTTPS | On by default (host-wide `OXPANEL_AUTO_HTTPS`, per site `auto_https_opt_out`): every site gets a certificate by itself a few seconds after it is created or its names change, and a sweep every 15 minutes retries failures. Before the authority is asked, the ACME client checks from outside the daemon that each name resolves and that every address it resolves to serves a probe file under the challenge path; names that fail are left out (the rest is still issued if the domain passes) and back off 1 h, 6 h, then daily — state kept across restarts. At most two checks/orders at once, one per site. A valid uploaded certificate is never touched; an expired one is replaced unless the site opted out. Suspended tenants are skipped and catch up on resume. `GetAutoHttpsStatus` / `oxpanel-ctl cert auto status`: covered / pending / partial / failed / uploaded / suspended / disabled, covered and skipped names with reasons, last and next attempt, last error; `RunAutoHttps` / `cert auto run [domain]` runs it now. |
| Any ACME authority | Let's Encrypt by default; any RFC 8555 directory via `OXPANEL_ACME_DIRECTORY_URL` (staging, ZeroSSL, Google Trust Services, private CAs). External Account Binding (required by ZeroSSL and Google) from a root-only file (`OXPANEL_ACME_EAB_FILE`), handed to the client as a systemd credential: never an argument, never logged, never returned. |
| The daemon stays offline | The daemon keeps `PrivateNetwork=yes`. OxPanel's own ACME client, `oxpanel-acme`, runs in a transient unit as the unprivileged account `oxpanel-acme` (no capabilities, read-only system, no homes, writable only its account, challenge and output directories). The daemon generates the key and the signing request itself; the client only ever sees the request, never a private key, and what it delivers is validated like an upload. |
| Private keys | One root-only file per site in `/etc/pki/oxpanel` (`0700`/`0600`). Never logged, never on a command line, never in a record or response. Stored PEM is rebuilt from the validated blocks, never the bytes sent. |
| Nginx | `listen 443 ssl http2` on IPv4 and IPv6 serving exactly the same site (PHP gets `HTTPS=on`, applications `X-Forwarded-Proto: https`); TLS 1.2 + 1.3, ECDHE AEAD suites only, shared session cache, no session tickets, no OCSP stapling. Per-site `redirect_https` (301, ACME challenges still answered on port 80) and `hsts` (one year, off by default). A 443 catch-all rejects the handshake for unknown names and for clients without SNI, so no tenant's certificate is ever shown for a name it does not own. |
| Status | `VirtualHost.certificate`: source (uploaded/ACME), issuer, not-before/not-after, names, uncovered names, install time — for expiry warnings in the panel. `GetHostInfo` reports `tls_available`, `acme_available` and the ACME directory. |
| Lifecycle | Reconfiguring a site keeps its certificate; removing the site removes certificate, key and any ACME leftovers. A suspended site answers 503 on both ports with its own certificate, does not redirect and answers no ACME challenges; certificates cannot be requested for it and renewals wait until it is resumed. |
| SELinux | Works enforcing: keys and certificates are `cert_t` (under `/etc/pki`), the challenge directory is `httpd_sys_content_t` via the shipped module; nothing else of the ACME client's directories is readable by the web server. |
| Reconciliation | A certificate file that differs from the record, or a missing or non-root-only key, is `TLS_CERTIFICATE_DRIFT`; a stray file in the certificate directory is `ORPHAN_TLS_FILE`; Automatic HTTPS state of a site that does not exist is `ORPHAN_AUTO_HTTPS_STATE`. |

Port 443 (and 80, for HTTP-01) must be opened in the firewall by the operator; OxPanel does not manage it.

## SFTP access

| Feature | Detail |
|---|---|
| SFTP only | `AddSftpKey` / `RemoveSftpKey` / `ListSftpKeys` and `SetSftpPassword` / `ClearSftpPassword` (`oxpanel-ctl sftp add-key|remove-key|list-keys|set-password|clear-password`). A tenant with a key or a password can log in with any SFTP client — and do nothing else: no shell or command, no terminal, no TCP/socket/agent/X11 forwarding, no tunnels (`ForceCommand internal-sftp`, `DisableForwarding`, every key line `restrict`). |
| Confined to its own home | sshd chroots the tenant into a root-owned directory that contains nothing but its home, bind-mounted at its real path (`/home/<t>`): other tenants, `/home` itself and the rest of the system are not visible at all. The home keeps its owner, mode and ACLs; the mount is a systemd mount unit, enabled, so it survives a reboot. |
| Files just work | Uploads belong to the tenant and inherit the home's default ACL and SELinux label (same inodes), so Nginx serves them and PHP and applications read and write them; files written by PHP and applications can be downloaded and removed over SFTP. |
| Keys only OxPanel can change | Keys are validated strictly (one `id_*.pub` line, no options; Ed25519, ECDSA, RSA 2048–16384 bits, FIDO variants; DSA refused; blob decoded and checked; OpenSSH `SHA256:` fingerprint), at most 20 per tenant, stored in the record and rendered to `/etc/oxpanel-sftp/<t>` (root-owned, readable only by that tenant). A compromised site cannot add a key. |
| Passwords, opt-in per tenant | A tenant has no SFTP password until one is set; it can be cleared again. Password tenants are in a second group whose `Match` block repeats the whole confinement and only adds password authentication; tenants without a password are never asked for one. The password (12–256 characters, no control characters; further policy is the panel's) goes to `chpasswd` on **stdin** — never in an argv, the journal or a record — and exists only as the system hash; it is never returned. `OXPANEL_SFTP_PASSWORDS=false` forbids them host-wide (`GetHostInfo.sftp_passwords_allowed`; default: allowed). `MaxAuthTries 3` for tenants on top of OpenSSH's own `PerSourcePenalties`. |
| Customers manage their own access | Key and password RPCs need the `vhost` scope (listing: `read`), so a customer-tier peer can manage SFTP access; nothing else about scopes changed. |
| Every tenant confined | All tenant accounts are in the group `oxpanel-tenants`, and OxPanel's own sshd drop-in (`/etc/ssh/sshd_config.d/60-oxpanel.conf`; `sshd_config` is never edited) applies to that group only — also to tenants without keys, so writing `~/.ssh/authorized_keys` gives a tenant nothing. The drop-in is validated with `sshd -t` before sshd is reloaded and rolled back if rejected; before a key is accepted, `sshd -T` must confirm the tenant would really be confined. Root and every other account are unaffected. |
| Lifecycle | Suspension withdraws the keys file, locks the password hash (resume unlocks the same hash; the plaintext is never kept) and ends running sessions (every session lands in the tenant's `user-<uid>.slice`, which also applies the tenant's limits to it). Removing a key or the password stops new logins with it; running sessions continue unless `end_sessions` is set. Removing the last credential removes keys file, mount and chroot (a mount still in use by an open session is removed at the daemon's next start). Deleting a tenant removes all of it first. |
| Reconciliation | `SFTP_ACCESS_DRIFT` (including a password the account has that the record does not, or the reverse, and an empty password field), `ORPHAN_SFTP_ACCESS`, `SSHD_CONFIG_DRIFT`; quotas: `DISK_QUOTA_DRIFT` (kernel limit differs from the record, or the host stopped enforcing quotas). |
| SELinux | Works enforcing with zero denials (key and password logins, uploads, serving, PHP, sessions). |

## Databases (MariaDB)

| Feature | Detail |
|---|---|
| Optional, detected | MariaDB 10.4+ (AlmaLinux 9: 10.5) is an optional host package. `GetHostInfo.database_engines` reports whether it answers and its version; every database request is refused with `FAILED_PRECONDITION` — before anything is recorded — when it is not installed, not running, or root may not connect. |
| Databases and users per tenant | `CreateDatabase`, `ListDatabases` (with the size of data and indexes), `DeleteDatabase` (moves it to the tenant's trash); `CreateDatabaseUser`, `ListDatabaseUsers`, `SetDatabaseUserPassword`, `DeleteDatabaseUser`; `GrantDatabaseAccess` / `RevokeDatabaseAccess`. Idempotent and resumable like every other RPC (records with `provisioning` / `ready` / `deleting`). |
| Names that cannot collide | `<tenant>_<suffix>`, suffix `a-z 0-9` (1–24). The suffix cannot contain `_`, so the owner is the text before the last `_`: `acme_shop_wp` belongs to tenant `acme_shop` and tenant `acme` can never create it. At most 57 characters, inside MariaDB's limits (64 for databases, 80 for users) and PostgreSQL's (63). |
| Own it or leave it | Records under `/var/lib/oxpanel/{databases,db-users}` are the proof of ownership. A name that exists on the server without a record is refused, never adopted, and never dropped; MariaDB's own schemas and accounts (`mysql`, `information_schema`, `performance_schema`, `sys`, `root`, `mariadb.sys`, …) cannot even be named. A new database is also refused if an account OxPanel does not manage holds a pattern grant (such as the stock anonymous `test\_%`) that would cover it. |
| Least privilege | Accounts are `'<name>'@'localhost'` only (UNIX socket), created with no privileges, and granted on databases of the *same* tenant only: `SELECT, INSERT, UPDATE, DELETE, CREATE, DROP, REFERENCES, INDEX, ALTER, CREATE TEMPORARY TABLES, LOCK TABLES, EXECUTE, CREATE VIEW, SHOW VIEW, CREATE ROUTINE, ALTER ROUTINE, TRIGGER`. Never `GRANT OPTION`, `EVENT`, or any global privilege (`FILE`, `PROCESS`, `SUPER`, `SHOW DATABASES`, …). The database in `GRANT … ON` is a pattern: `_` is escaped, so a grant on `acme_shop` does not also cover `acmeXshop`. |
| No SQL injection, no secret leaks | SQL is sent on the `mariadb` client's standard input; the argument vector is constant. Identifiers are allow-list validated *and* quoted. The password is hashed by the daemon (`mysql_native_password`) and only the hash is sent, so the plaintext reaches no argument vector, no server process list or log, and no journal; the client's error output is withheld for statements that carry the hash. The password is never recorded or returned; 8–128 characters are enforced engine-side. |
| Limits | `MAX_USER_CONNECTIONS` per account (default 25), at most 20 databases and 20 users per tenant (all configurable). |
| Tenant lifecycle | `DeleteTenant` is refused while the tenant owns databases, database users or trash (data is only dropped on an explicit request; the cascade drops everything at once). Suspension locks every database account of the tenant (`ACCOUNT LOCK`) and ends its open sessions; users created while suspended are born locked; resume unlocks them. |
| Database trash | `DeleteDatabase` does not dump and does not drop: the database's grants are revoked and the sessions of the users that held them are ended (a revoked grant otherwise keeps working for a session inside the database, and MariaDB keeps grants after `DROP DATABASE`), its views, triggers, routines and events are captured, and its tables are moved with one `RENAME TABLE` into a hidden schema `oxpanel_trash_<id>` that no tenant can name or be granted. The name is free at once, and a new database of that name gets none of the old grants. Purged automatically after 30 days (`OXPANEL_DB_TRASH_DAYS`; checked at start-up and hourly); `ListDatabaseTrash`, `PurgeDatabaseTrash` (one or all, the customer may empty it early). |
| Trash cap | Trash never counts against the disk quota (database files belong to `mysql`), but its total size per tenant is capped: `ResourceLimits.db_trash_max_bytes`, default the tenant's disk limit. A delete that would exceed it is refused before anything changes, with a message to empty older trash first. |
| Restore from the trash | `RestoreDatabaseTrash` always needs a new name of the same tenant (refused if it exists); tables come back with one `RENAME TABLE`, views, triggers, routines and events are re-created, and the database has no grants until the customer grants it. An object that cannot be re-created (or whose definer is not one of the tenant's users) is returned with its definition; table data never depends on it. Interrupted moves and restores are completed by repeating the request. |
| Stored objects re-created safely | A tenant can write a routine body that makes `mariadb-dump \| mariadb` run SQL as root (the client and the server do not split comments alike; demonstrated on MariaDB 10.5). OxPanel never replays such text through the client's statement splitter: views go through `EXECUTE IMMEDIATE` from a hex literal; every other object is replayed in its own client process with `--binary-mode --sandbox` under a delimiter absent from its text, a definition containing `\C` or NUL is refused, and no object with a definer outside the tenant is created. |
| Reconciliation | `DATABASE_MISSING`, `DATABASE_USER_MISSING`, `DATABASE_PRIVILEGE_DRIFT` (a privilege added by hand, a lost grant, a lock or connection limit that differs from the record, an unmanaged account that can reach a managed database or a deleted one in the trash) and `ORPHAN_DATABASE_OBJECT` (a database or account with a tenant's prefix but no record); `DATABASE_TRASH_DRIFT` (trash schema gone, interrupted move or restore, past its purge date) and `ORPHAN_DATABASE_TRASH` (a trash schema without a record). Read-only. |
| SELinux | Works enforcing with zero denials: PHP (in `httpd_t`) and applications (in `oxpanel_app_t`) connect to the MariaDB socket with the stock policy. |
| Ready for more engines | Every record and API message carries an engine (`DatabaseEngine`); PostgreSQL or MongoDB can be added beside MariaDB without renaming anything. |

## Backups and restores

| Feature | Detail |
|---|---|
| Jobs | `CreateBackup` and `RestoreBackup` return a job at once; `GetJob` reports `RUNNING`, `SUCCEEDED` or `FAILED` with a message and the end of the worker's output. The work runs in a transient systemd unit (`oxpanel-job-<id>.service`), so it is not bound by the 300 s request limit and survives a restart or crash of the daemon, which re-attaches to running jobs at start. One job per tenant, at most 4 on the host. |
| Contents | The tenant's home as a gzip'd tar (`home.tar.gz`), the engine's records of the tenant and its virtual hosts (`records.json`) and every database of the tenant (below), listed in a `manifest.json` with size and SHA-256 of each member. |
| Database dumps | Each ready database (not the trash) as `db-<name>.sql.gz` (kind `mariadb`: tables, data and views from `mariadb-dump --single-transaction`, as root over the UNIX socket — no password exists — in the job's sandbox, slice and priorities, within the same size budget) and `db-<name>.objects.json` (kind `mariadb-objects`: triggers, routines and events, captured by the daemon, never taken from dump text). A failed dump fails the backup and leaves nothing. The record, manifest and `ListBackups` list the databases with their size and members. Refused before anything exists when the tenant has databases and MariaDB cannot be used. |
| Restore a database | Separate from the files: `RestoreBackupDatabase` (and `RestoreRetainedBackupDatabase` for a deleted tenant's retained backup, `delete` scope) loads one database of a backup into a **new** name of the tenant, never over an existing one, as a job: checksum verified, dump loaded by `mariadb --binary-mode --sandbox`, stored objects re-created safely, anything with a foreign definer dropped and reported, no grants. A failed load removes the new database again. |
| Left out, and said so | `node_modules` at any depth, Python virtualenvs (any directory with a `pyvenv.cfg`, and every Python application's `.venv`), and the `.cache`/`.npm` download caches. A scan as the tenant lists what was left out in the record, the manifest and `ListBackups` (`excluded`, `excluded_count`, `exclude_rules`), and the free-space estimate does not count it. |
| Read as the tenant | `tar` runs with the tenant's uid (never root), stores symlinks as symlinks, skips what the tenant cannot read, records FIFOs and device nodes without opening them, handles sparse files, stays on one file system. It writes into a pipe; only a root worker without `CAP_DAC_OVERRIDE` writes the archive file. |
| Charged to the tenant | The job runs in the tenant's slice at the lowest CPU and I/O priority, sandboxed (`ProtectSystem=strict` with one writable path, no network), with a time limit (6 h by default). |
| Root-only storage, bounded | `/var/lib/oxpanel-backups/<tenant>/<id>/`, directories `0700`, files `0600`; tenants cannot list or read it. A backup is refused unless the home fits with a reserve to spare (1 GiB by default), and the archive may not grow into it. The newest 7 complete backups per tenant are kept (configurable). |
| Never half-written | A backup is listed `READY` only after the worker has written and synced the archive and the daemon has written the manifest; a failed, killed or interrupted backup leaves nothing behind. |
| Integrity | Size and SHA-256 are verified in full before a restore starts; a damaged or truncated archive is refused and nothing is restored. |
| Restore as the tenant | Into the home, with a required choice for files that already exist: `OVERWRITE` (replaced, never written through) or `KEEP` (left untouched, only missing files restored); there is no default. Newer files always stay; the job reports how many entries were restored and how many were kept. Extracted by `tar` running as the tenant in a sandbox where only the home is writable: absolute paths, `..`, writes through symlinks, hard links out of the home, set-uid/set-gid files and device nodes are all refused, and every file belongs to the tenant. PHP and applications are stopped during the restore; afterwards the home is made private again, relabelled, and every document root gets its web-server ACLs and SELinux label back, so the site is served without manual steps. Every application gets its virtualenv recreated and its dependencies reinstalled (as `InstallAppDependencies` does) before it starts; the result per site is in the job, and a failed installation does not fail the restore of the files. |
| Tenant isolation | A backup is only found for the tenant it belongs to (and the uid it was taken from): restoring or deleting another tenant's backup is `NOT_FOUND`. |
| Lifecycle | Suspended tenants can be backed up and restored (their services stay stopped). `DeleteTenant` is refused while the tenant has a running job or backups that are not retained; the cascade deletes the backups that are not retained. |
| Retained backups | A backup can be kept for 1–12 months or 1–366 days (`CreateBackup.retain_months`/`retain_days` or `RetainBackup`): exempt from the per-tenant count, kept after `DeleteTenant`, then removed automatically (checked at start-up and hourly). Backups of a deleted tenant are invisible to a later tenant of the same name; the operator lists them (`ListRetainedBackups`), deletes them early, or restores one into an existing tenant with `RestoreRetainedBackup` (backup id + former tenant + target, `delete` scope). |
| Reconciliation | `BACKUP_ARCHIVE_MISSING`, `BACKUP_ARCHIVE_MODIFIED` (size or manifest differs from the record), `ORPHAN_BACKUP_ARCHIVE`, `BACKUP_INCOMPLETE`. |
| Scheduling | Held in the engine, so backups run when the panel is down: `SetBackupSchedule` (`tenant` scope; `oxpanel-ctl backup-schedule set`) sets a tenant to off, daily or weekly, at an hour (UTC) chosen by the caller or assigned by the engine within `OXPANEL_BACKUP_WINDOW` (01–05); the minute is always the engine's, so tenants spread over the hour. Tenants without a choice follow `OXPANEL_BACKUP_SCHEDULE_DEFAULT` (off by default); `OXPANEL_BACKUP_SCHEDULES=false` stops all. A scheduled backup is an ordinary one: one job per tenant, at most 4 on the host, the free-space check, the same keep-count; suspended tenants are backed up too. |
| Scheduled backups: catch-up and results | After downtime only the most recent missed slot runs (once, not once per missed day); a new or changed schedule starts nothing at once. `GetBackupSchedule` (`read`) shows the schedule, the next run and the last scheduled run, job, result (`running`, `succeeded`, `failed`, `deferred`) and message. A failure is recorded and the next slot runs normally; a backup that cannot start yet (job limit, another job of the tenant) is deferred and retried. The schedule is a record that survives restarts and goes with the tenant; a schedule of a tenant that does not exist is `ORPHAN_BACKUP_SCHEDULE`. |

## File manager

| Feature | Detail |
|---|---|
| Runs as the tenant | Every operation is done by the engine's own worker running as the tenant (uid/gid, no groups, no capabilities, `no_new_privs`) inside the tenant's slice and disk quota — quick ones through `systemd-run --scope` + `setpriv`, long ones as a transient unit with `User=` the tenant. The kernel refuses whatever the tenant could not do over SFTP: another tenant's files, root's files, a hard link to someone else's private file. Never root. |
| Confined to the home | Paths are relative to the home and allow-listed (`FilePath`: no `..`, no absolute paths, bounded length and depth); the worker resolves each with `openat2(RESOLVE_BENEATH)` from the home, so a symlink out of the home (to `/etc/passwd`, another home) is never followed — listings show such links as leading outside. Names never reach an argument list (a name beginning with `-` is just a name); a name the engine creates must be visible text (no newline, control or invisible characters). |
| Browse, read, edit | `ListFiles` (paged, directories first), `StatFile`, `ReadFile` (1 MiB per call), `WriteFile` (atomic editor save), `SearchFiles` and `GetDirectorySize` (bounded in entries and time). FIFOs and devices are never opened. |
| Uploads of any size | `StartUpload`, `UploadChunk` (192 KiB, retry-safe), `FinishUpload` (size and SHA-256 checked), `AbortUpload`: content grows in a hidden partial file and replaces the target only when complete; a quota-exceeded or abandoned upload leaves nothing behind. |
| Organise | `MakeDirectory`, `MoveFile`, `SetFileAccess` (private, web-readable, or a mode up to 0775 — never set-uid/set-gid/sticky or world-writable; on document roots the group bits are the ACL mask, so the web server can never get more than the engine granted). New files get the mode, inherited ACL and SELinux label the tenant's own tools give them (0644/0755, 0640/0750 under a document root), and are served without further steps. |
| Jobs | `CopyFiles`, `DeleteFiles`, `CompressFiles` (zip, tar.gz) and `ExtractArchive` (zip, tar, tar.gz) run as jobs that outlive the request and a restart of the engine (`GetFileJob`, `ListFileJobs`); each call waits 2 s so small jobs come back finished. One job per tenant, 8 per host. Copies keep holes, links and modes; deletion removes links, never their targets. |
| Hostile archives | Absolute names, `..`, links leading out of the destination, hard links out of it, devices and FIFOs are skipped; nothing is written through a symlink; modes are capped at 0755; zip/tar/gz bombs are stopped by a ratio (200×) and size (8 GiB) limit and an entry limit (100 000) while streaming, leaving no partial file. Compression never follows a symlink and never archives a file the tenant cannot read. |
| Protected directories | The home, every document and application root, and the directories leading to them cannot be deleted, moved or closed through the file manager. |
| Scopes and suspension | Listing needs `read`; reading content and every change need `vhost`. A suspended tenant's files can be read but not changed, and its running job is stopped. `DeleteTenant` (also with `cascade`) waits for a running file job; while a cascade deletion runs, files can be read but not changed. |

## DNS hosting

| Feature | Detail |
|---|---|
| Authoritative DNS server | BIND 9 from AlmaLinux's AppStream (`bind`, an optional package: detected, reported in `GetHostInfo.dns`, every DNS request refused with `FAILED_PRECONDITION` before anything is created when it or the public suffix list is missing). OxPanel runs it as its own service, `oxpanel-dns.service`, with a configuration it owns entirely (`/etc/named/oxpanel`, `/var/lib/oxpanel-dns`); the distribution's `/etc/named.conf` and `named.service` are never touched. Off until the operator sets `OXPANEL_DNS=true`. |
| Hardened server | Authoritative only (no recursion, no cache: not an open resolver, also not for the host), zone transfers only with the TSIG key, no dynamic updates, NOTIFY only to configured secondaries, version/host name/server id hidden, response-rate limiting, control channel on the loopback with a root-only key. named drops to its account and runs in the packaged `named_t` domain; the unit adds `ProtectSystem=strict` (only `/var/lib/oxpanel-dns` writable), no homes, a minimal capability set and a system-call filter. |
| Name servers | `OXPANEL_DNS_NAMESERVERS` (the NS records of every zone), `OXPANEL_DNS_SOA_CONTACT`, the host's public `OXPANEL_DNS_IPV4`/`OXPANEL_DNS_IPV6` (required, never guessed from interfaces), default and negative TTL, limits. Incomplete settings are refused at start (`--check-config`). `GetHostInfo.dns`: settings, server version and state, zone count, warnings (one name server; no secondary — one server answering as all names works but has no redundancy; the stock `named.service` running). |
| Secondaries | `OXPANEL_DNS_SECONDARIES`: NOTIFY and zone transfers signed with TSIG (`hmac-sha256`, key generated by the engine into `/etc/named/oxpanel/transfer.key`, root:named 0640 — never in argv, logs or responses). A catalog zone lets any catalog-capable secondary (BIND, Knot, PowerDNS) learn every zone by itself; it need not be an OxPanel host. |
| Automatic zones | When DNS hosting is on, a site's names get address records in a zone created by itself for each name's registrable domain (from the host's public suffix list: `shop.example.co.uk` → `example.co.uk`), unless the tenant already has the zone. Following alias changes; an automatic zone goes with its last site unless the tenant added records to it. Per site opt-out (`dns_opt_out`, `vhost set --no-dns`) for domains whose DNS is elsewhere. `VirtualHost.dns_zone` says which zone holds the site's records. |
| Zones | `CreateDnsZone`, `ListDnsZones`, `GetDnsZone` (every record, the protected ones marked), `DeleteDnsZone`, `ResetDnsZone` (back to the engine's records). A zone belongs to exactly one tenant; another tenant's zone is `NOT_FOUND`. Zones never overlap, never are a public suffix, never are or contain the engine's catalog zone or a special-use domain (`.invalid`, `.localhost`, `.local`, `.arpa`, `.onion`, `.alt`) and never contain another tenant's sites; a site of tenant B inside tenant A's zone gets no records. At most 50 zones per tenant (configurable). |
| Records | `AddDnsRecord`, `UpdateDnsRecord`, `RemoveDnsRecord` for A, AAAA, CNAME, MX, TXT, SRV, CAA and NS (delegation below the apex). Allow-list validation of every field (names relative to the zone, labels and lengths, `_` where the DNS allows it, leftmost wildcards, parsed addresses, host-name targets, TTL 60 s–1 week, number ranges); TXT split into 255-byte strings, escaped and quoted by the engine; CNAME exclusivity, no CNAME at the apex, MX/SRV never pointing at a CNAME, delegations take only NS and glue, one TTL per record set; at most 500 records per zone. Identical requests change nothing. |
| Protected records | The SOA, the apex NS records and the A/AAAA records of every name of the tenant's sites are maintained by the engine, shown as protected and cannot be added to, replaced or broken by the tenant. No CAA and no mail records by default (a hook is in place for OxPanel's own mail). |
| External mail | MX records with priorities at the apex and on subdomains, SPF as TXT (longer than 255 characters), DKIM as TXT on `selector._domainkey` (2048-bit keys) or as a provider's CNAME, DMARC on `_dmarc`, verification TXT/CNAME records, SRV for autodiscovery, null MX; MX targets that are CNAMEs are refused. |
| Validate → activate → roll back | Zone files are rendered from records only (one line per record, no `$` directives) and checked with `named-checkzone` on a staging copy before they replace the live file; the server configuration is checked with `named-checkconf` and restored if rejected. A rejected change leaves record, file and served zone untouched and returns the checker's reason; a zone whose creation the configuration checker rejects leaves nothing behind. The server is reloaded until it has loaded what was written (a marker survives a crash or a failed reload), so an interrupted change is completed by the next one or by the daemon's start. Only the changed zone is reloaded (`rndc reload <zone>`, run in a transient unit: the daemon has no network); new and removed zones are a `reconfig`. |
| Serials | A new serial exactly when a zone's content changes: the current time, or the previous serial + 1 if that is not later (RFC 1982). Kept across restarts and clock steps, always accepted by secondaries; switching DNSSEC on or off issues one above anything served. |
| DNSSEC | `SetDnssec` per zone (`dns dnssec <zone> on|off`): BIND's own automatic signing (`dnssec-policy`, inline signing): one ECDSA P-256 key (algorithm 13), kept until unsigned (no rollover, so the registrar's DS never changes), NSEC3 without salt or iterations. Private keys belong to the server's account (0600), never read by the engine, never returned. `GetDnsZone` returns state, DS and DNSKEY records for the registrar. Switching off is refused while the parent publishes a DS (and, without `force`, when that cannot be checked). Secondaries serve the signed zone. |
| Outside checks | `CheckDnsZone` (`dns zone-check`): whether the public DNS delegates the domain to the configured name servers (delegated / partial / elsewhere / not found / unknown, with what to do), the DS records at the parent and whether they match, and the serial each name server serves — asked by `oxpanel-daemon dns-probe` in a transient unit under a dynamic unprivileged user, because the daemon has no network. |
| Tenant lifecycle | A suspended tenant's zones keep answering unchanged (mail and other services depend on them; its sites answer 503); changing them waits for the resume. `DeleteTenant` is refused while the tenant owns zones; `dns::remove_tenant_zones` removes them in order for a cascading delete. Zone data is engine records, not tenant files: it is not in tenant backups. |
| Reconciliation | `DNS_ZONE_DRIFT` (zone file differs from the records or is missing, the server does not serve the recorded serial, an interrupted creation), `ORPHAN_DNS_FILE`, `DNS_SERVER_DRIFT` (configuration or keys differ or are missing, key readable by others, server not running), `DNS_SECONDARY_DRIFT` (a secondary serves another serial or not the zone), `DNSSEC_DRIFT` (a signed zone without its key, keys of an unsigned zone). |
| SELinux | Works enforcing: named in the packaged `named_t` domain, its configuration `named_conf_t` (under `/etc/named`), its data `named_cache_t` (the shipped module labels `/var/lib/oxpanel-dns`). |

## API, transport and authentication

| Feature | Detail |
|---|---|
| gRPC over a UNIX socket only | `/run/oxpanel/oxpanel.sock`, `root:oxpanel 0660`. There is no TCP listener and no TLS — nothing to expose. |
| Kernel-verified peers | Every connection is authenticated with `SO_PEERCRED`. Allowed: uid 0 (configurable), uids in `OXPANEL_ALLOWED_UIDS`, and accounts whose primary or supplementary group (from the account database) is in `OXPANEL_ALLOWED_GIDS` or is the socket group. Unauthorised peers are closed **before** any HTTP/2 is parsed. |
| Fail-closed interceptor | A request without verified peer information is refused with `PERMISSION_DENIED`. |
| Strict input validation | Allow-list newtypes for user names (`^[a-z][a-z0-9_-]{2,31}$`), domains (lower-case ASCII / punycode labels, no wildcards, no IPs), document roots (no `..`, no metacharacters), owner labels, and limits (memory ≥ 16 MiB or unlimited, weights 1–10000). Invalid input never reaches the OS. |
| Precise error codes | `INVALID_ARGUMENT`, `ALREADY_EXISTS`, `NOT_FOUND`, `FAILED_PRECONDITION`, `RESOURCE_EXHAUSTED`, `PERMISSION_DENIED`, `DEADLINE_EXCEEDED`, `INTERNAL`. Internal failures are redacted for the client and logged in full to the journal. |
| Limits | Requests capped at 256 KiB, 16 concurrent streams per connection, 300 s per request, HTTP/2 keep-alive. |
| Per-peer scopes | `OXPANEL_PEER_SCOPES=uid:scope+scope,…` confines an authenticated peer to `read`, `vhost`, `tenant` and/or `delete` RPCs; anything else is refused with `PERMISSION_DENIED` before validation or any OS call. Unlisted peers keep full access. A customer-facing service account limited to `read+vhost` can never reach `DeleteTenant`. |
| Serialised mutations | One global lock: exactly one tenant/vhost mutation runs at a time (the account database, Nginx and systemd are not transactional). |

| Host information | `GetHostInfo`: engine version, SELinux and dry-run state, tenant and virtual-host counts, the tenant uid range (capacity), load averages, memory, uptime, size/free space of the file system holding tenant homes, whether certificates can be installed and requested (and from which ACME directory), whether SFTP can be offered, each database engine (available, version, databases and users), whether disk quotas are enforced (with what to change if not), and the size and free space of the backup store and the number of backups kept per tenant; whether `php-cli` is installed, the PHP maxima, the task limits and the backup-schedule switch and default. |
| Reconciliation | `Reconcile` compares every record with the operating system and reports differences: interrupted tenants, missing or mismatched accounts, invalid homes, edited or missing unit files, missing or edited Nginx files, virtual hosts without a tenant, and orphan files in OxPanel's own directories. Strictly read-only — most findings are healed by repeating the original request. `oxpanel-ctl host reconcile` exits `3` when drift is found. |
| Configuration | Environment variables `OXPANEL_*` (from `/etc/oxpanel/daemon.env`); every value has a production default. `--check-config` validates configuration and host prerequisites without starting. |
| Preflight | Refuses to start without root, without the required tools (`useradd`, `userdel`, `nginx`, `systemctl`, `setpriv`, `setfacl`, `mkdir`, `du`, and on SELinux hosts `restorecon`, `semanage`), if the socket group does not exist, or if the web user is root / a tenant. |
| systemd integration | `Type=notify` readiness, clean shutdown on `SIGTERM`/`SIGINT` (socket removed), logs via `tracing` to the journal, `RuntimeDirectory`/`StateDirectory` managed by systemd. |
| Hardened unit | `ProtectSystem=strict` with an explicit `ReadWritePaths` list, `PrivateNetwork` + `IPAddressDeny=any`, `NoNewPrivileges`, `PrivateDevices`, `ProtectKernel*`, `RestrictNamespaces`, `MemoryDenyWriteExecute`, capability deny-list, seccomp allow-list. |
| Packaging | RPM spec (`packaging/oxpanel-daemon.spec`), `sysusers.d` (the `oxpanel` group, the `oxpanel-acme` account, the `oxpanel-tenants` and `oxpanel-sftp-password` groups), `tmpfiles.d`, environment file. |
| Release and installer | `make dist` collects the engine RPM (with the `oxpanel-acme` client), `install.sh`, the handbook and a `SHA256SUMS` file in `dist/release/`; nothing is tagged, signed or uploaded. `install.sh` is a one-command installer for a fresh AlmaLinux 9 host: separate, logged stages (prerequisites, Node.js 22 stream, engine RPM, SELinux booleans and policy module, Nginx, MariaDB installed and hardened as HANDBOOK 3.5 says, PHP-FPM and php-cli with the shared pool masked, daemon, optional DNS hosting (BIND as `oxpanel-dns`, the operator's name servers and public addresses, never guessed; an existing `named.service` stops the run unless `--disable-stock-named`), firewalld 80/443 (and 53 with DNS) only when firewalld is running, final `--check-config` / `host info` / `host reconcile`), idempotent (a second run changes nothing and says so) and resumable. Every question is answerable by flag or answers file, and `--yes` is safe (no EPEL, no fail2ban, no boot change, no reboot, no touching an existing MariaDB or in-use PHP-FPM). Optional hook for a panel RPM (`panelapi` in group `oxpanel`, optional peer scopes). Design record: `docs/superpowers/specs/2026-11-13-installer-design.md`. |
| Login banning (fail2ban) | Offered by the installer: enables EPEL only on request, installs `fail2ban-server`, and writes a jail for sshd that reads the journal (works with SELinux enforcing), bans an address after 5 failed SSH/SFTP logins in 10 minutes for 1 hour (growing to a week), through firewalld rich rules (or nftables where firewalld is not running), and never bans loopback, the operator's session address or `--ignore-ip` addresses. |
| Disk-quota boot setting | Offered by the installer: detects whether the file system holding the homes is XFS with user quotas; if not, explains and (when asked) adds `rootflags=uquota` with `grubby`, or `uquota` to the `/etc/fstab` line when the homes are on a file system of their own, says a reboot is needed and either reboots when told to or prints exactly what remains. A run after the reboot notices that quotas are active and finishes. |
| Uninstall and upgrade | `install.sh --uninstall` removes the engine packages and OxPanel's own additions and never customers' homes, databases (nor their trash), backups, certificates, DNS zones and signing keys or the sites' Nginx files (it says that hosted domains stop resolving until a reinstall), and lists what it left; installing again finds the tenants from their kept records. Installing a newer RPM through `install.sh` upgrades in place (tenants, sites, limits and records survive; the daemon re-renders configuration at start). |
| Dry-run mode | `--dry-run` runs the full daemon against an in-memory fake OS as an unprivileged user — for developing the panel without root. |
| Records | Everything the daemon owns is recorded in `/var/lib/oxpanel/{tenants,vhosts,databases,db-users,backups,jobs,tasks,backup-schedules,dns-zones}/*.json` (and Automatic HTTPS state in `auto-https/`) (root-only). A corrupt record blocks operations on that one object only. |

## Engineering guarantees

- Rust, `#![forbid(unsafe_code)]`, clippy pedantic with warnings as errors, no `unwrap`/`expect`/`panic` in production paths.
- No shell anywhere: every external program is an absolute path with an argv array; the only module that spawns processes is `system/real.rs`.
- Tests: `make test` runs 442 tests against a fake OS (374 unit tests of the daemon with exact argv assertions, among them the DNS stream's property tests of its validators, zone renderer and wire parser; 9 of the ACME client, 1 of `oxpanel-ctl`, 32 property tests of every validator and renderer, 12 gRPC-surface tests: scope decisions generated from `panel.proto`, malformed/oversized/unknown-field frames, concurrent clients; 3 crash-safety tests that interrupt every tenant, site, PHP and application workflow at every external command (the HTTPS, SFTP, database and backup workflows have their own resumability tests, outside that matrix), 10 end-to-end gRPC tests over a real UNIX socket, 1 performance-budget test); a 1219-check root integration suite in an AlmaLinux 9 systemd container (including HTTPS with OpenSSL-made certificates, and ACME, Automatic HTTPS and External Account Binding end to end against a local Pebble test CA); and `make acceptance`: the checks on a real AlmaLinux 9 VM (counted per phase in each run's report) with SELinux enforcing (install from git or RPM, SELinux labels and zero AVC denials, sandbox namespaces, restart/kill/resume, reboot, soak, tenant-isolation attacks run from inside tenants' PHP, Node.js and Python code, and real-host performance). Line coverage of the daemon: see `docs/COVERAGE.md`. Every row of this document is traced to named tests (`docs/traceability.map`, enforced by `make check`); threat model: `docs/SECURITY.md`; performance and budgets: `docs/PERFORMANCE.md`; manual QA script: `docs/QA_PLAN.md`. `cargo-deny` for advisories/licences/bans.
- Builds without a system `protoc` (pure-Rust `protox`) and without a host toolchain (everything runs in the AlmaLinux 9 container).

## Not yet included

To be explicit, v0.2.0 does **not** provide: ACME DNS-01 or wildcard certificates from ACME, OCSP stapling, a choice of PHP version or PHP settings beyond the eight of `SetPhpSettings` (the host's `php-fpm` package is used as installed), a free command line, environment variables or catching up missed runs for scheduled tasks, e-mailing task output, backup schedules other than daily or weekly, a choice of Node.js/Python version per application (the host's packages are used; Node.js must be 22 or newer), other runtimes, custom start commands or environment variables for applications, a confining SELinux policy for applications, DNS beyond what "DNS hosting" lists (DNSSEC key rollovers, dynamic updates, geo or weighted answers, reverse zones, a registrar integration, mail records by default), mail, database engines other than MariaDB, remote database access, per-database size quotas, FTP or SSH shell access for tenants, disk quotas on file systems other than XFS (or project quotas), off-host, encrypted or incremental backups, automatic repair of drift found by `Reconcile`, a confined SELinux domain for the daemon itself, or historical metrics. These are on the roadmap in `oxpanel-daemon/PROJECT_DETAILS.md`.
